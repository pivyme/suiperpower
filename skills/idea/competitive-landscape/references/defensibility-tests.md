# Defensibility tests

Apply these to the candidate's angle to test whether the differentiation holds.

## The one-sentence test

Can the user state the angle in one sentence that names a specific competitor and a specific advantage? If not, sharpen until they can.

Bad: "We have better UX than Compound."
Better: "We let Sui users borrow against Walrus-stored proof-of-storage in a single PTB; Compound has no equivalent on any chain."

The bad version is generic. The better version is specific (named primitive, named competitor, named advantage).

## The cheap-extension test

Can an existing on-Sui incumbent add the candidate's feature in a sprint?

If the answer is yes, the moat is not the feature; it is timing, distribution, or audience. The user must articulate which.

If the answer is no (because the feature requires a primitive the incumbent has not adopted, or a different mental model), the moat may be technological. Confirm by naming the primitive.

## The port-from-EVM test

Can an EVM incumbent in the same category port to Sui in a sponsor-funded weekend?

If yes, the moat must be Sui-native (depends on Object model, Walrus, DeepBook, Kiosk, zkLogin, parallelism). "First on Sui" is not a moat once a sponsor weekend lowers the porting cost.

If the moat is genuinely Sui-native, name the specific primitive in the angle sentence.

## The audience test

Can the user reach the audience? Or does the moat assume distribution that does not exist?

A clever feature without distribution loses to a generic feature with distribution every time.

## The web2 test

Why would a user pick the candidate over the off-chain alternative?

If the answer is "decentralization", the candidate has a problem. Most users do not buy decentralization as a feature; they buy outcomes (speed, cost, ownership, composability) that decentralization enables. Restate in outcome terms.

## The 6-month test

In 6 months, will the candidate's angle still be the angle? Or will the chain catch up, the incumbent extend, or the audience move?

A 6-month-stable angle is the bar. Anything shorter is a wedge that needs a follow-on plan.

## The 5-friend test

If the user described the angle to 5 friends in the Sui community, would they nod or push back?

Push-back is often more useful than nodding. If 5 friends all nod, the angle is too generic to test. If 1-2 push back hard, the user has identified the controversial premise; sharpen the angle around defending it.

## Anti-pattern angles

Reject these as defensible angles:

- "We are first to market." (Lasts weeks at best.)
- "We have a community." (Communities follow products, not vice versa, until late stage.)
- "We have better UX." (True for everyone; not differentiating.)
- "We are open source." (Most Sui projects are.)
- "We will iterate faster." (Every founder believes this.)
- "We have a great team." (Necessary, not sufficient.)
- "We are AI-powered" or "AI-augmented" or any AI-prefixed claim with no substance.

Defensible angles name a specific user, a specific primitive, a specific competitor, and a specific advantage. Less than that is positioning theater.
